# 品牌与门店主数据

适用版本：V1 品牌与门店生命周期

更新日期：2026-08-20

## 1. 权限与边界

只有最高权限 `OWNER` 可以进入“系统设置 → 品牌与门店”。页面集中维护品牌编码、品牌名称及全部门店，并展示各门店当前店长、在职员工数、服务区数量和服务位启用情况。

门店不执行物理删除。停用只阻止门店进入新的业务选择器，顾客、订单、支付、库存、服务档案、员工任职和审计历史均保留。最高权限账号可查看全部有效门店，不依赖逐店授权；其他角色仍只能访问明确分配的有效门店。

## 2. 品牌资料

品牌编码是品牌的永久唯一标识，由平台批准入驻时自动生成，格式为 `B + 日期 + 四位当日流水号`。创建后页面只读，后端同样拒绝改码；品牌改名只修改名称，不影响门店、会员、订单或其他关联数据。名称最长 100 字。保存时携带版本号，其他管理员已经修改时不会静默覆盖。

## 3. 新增与编辑门店

| 字段 | 是否必填 | 规则 |
|---|---|---|
| 门店编码 | 系统生成 | 品牌内按 `S001`、`S002`、`S003` 递增；创建后不可修改 |
| 门店名称 | 必填 | 最长 100 字 |
| 业务时区 | 必填 | 必须是 Linux/.NET 可识别的 IANA 时区；中国门店使用 `Asia/Shanghai` |

新增门店时只填写名称和业务时区，编码由后端自动分配。新门店创建后默认有效。负责人应继续在“员工与权限”分配店长和员工，再到“门店设施配置”建立服务区与服务位；门店创建本身不会复制其他门店的人员、设施、库存或业务数据。

## 4. 停用与恢复

停用或恢复都必须填写 2–200 字原因并进入审计。以下情况不能停用：

- 当前只剩这一家有效门店；
- 门店仍有使用中或暂停中的设施；
- 门店仍有未完成接待或未完成消费单；
- 门店仍有待交班或待复核班次。

停用后当前门店选择器会自动切换到仍有效的门店。恢复门店不会自动修改员工授权或设施状态，负责人应先检查人员、价格、库存和支付配置再恢复营业。

## 5. 数据库与审计

本功能复用既有品牌、门店和乐观锁字段，通过仅向前迁移新增业务编码序列表。新增门店、编码分配与创建审计在同一事务内完成；品牌和门店编码均由应用层强制保持不变，唯一约束由 PostgreSQL 最终保护。资料修改、创建、停用和恢复分别记录操作者、前后状态、原因和追踪号。
