# 本地启动、登录与权限

适用版本：V1 开发基线  
更新日期：2026-08-19

## 1. 启动本地系统

1. 按仓库根目录 `README.md` 准备 `.env`。正式密码不得写入代码或提交到 Git。
2. 启动 PostgreSQL：`docker compose up -d postgres`。
3. 载入 `.env` 后启动 API：`dotnet run --project apps/api/Erp.Api`。
4. 启动前端：`npm --prefix apps/web run dev`。
5. 浏览器访问终端显示的本地前端地址。

API 存活检查地址为 `/health/live`。本地开发允许 HTTP；非 Development 环境必须使用 HTTPS、Secure Cookie 和 HSTS。

## 2. 登录

![登录页面](assets/01-login.png)

输入员工账号和密码后点击“进入工作台”。

- 员工账号：必填，最长 100 个字符。
- 密码：必填，最长 256 个字符。
- 在此设备保持登录：可选；只应在受控门店设备上使用。
- 连续失败：同一来源 15 分钟内最多尝试 10 次；超过限制会暂时拒绝请求。
- 错误提示：不会说明账号是否存在，以免泄露员工账号信息。

## 3. 进入工作台

![经营工作台](assets/02-dashboard.png)

登录后顶部会显示当前门店、消息通知、使用帮助、权限范围内的系统设置，以及当前员工和角色。点击右上角头像可修改密码或退出登录。左侧菜单按业务模块进入，其中“价格管理”用于查看当前价格、安排调价和追溯历史价格。当前 V1 基线中的经营数字来自真实业务汇总；没有业务时显示零或“暂无数据”，不会使用演示数字冒充实际经营数据。

当前门店下拉框只列出该账号被授权的门店。切换门店只改变操作上下文，不扩大账号权限。

## 4. 权限与退出

- 系统负责人 `OWNER`：可以进入全部商户页面；高风险动作仍受原因、状态、审批、职责分离和审计限制。
- 门店店长 `STORE_MANAGER`：可以进入授权门店的经营、设施、排班、顾客、收银、库存、供应链、报表、审计和设施配置页面，不能维护组织、员工权限、全局价格或支付密钥。
- 前台 `FRONT_DESK`：可以进入工作台、设施接待、预约、顾客和只读目录，不能进入收银、库存、报表和系统设置。
- 收银员 `CASHIER`：可以进入工作台、顾客、收银和只读目录，不能进入设施操作、库存、报表和系统设置。
- 服务员工 `TECHNICIAN`：当前只能进入工作台和只读目录，不展示顾客、金额、库存、报表或审计页面。
- 同一员工兼任多个角色时，页面和动作权限取并集。
- 所有写请求都要求登录 Cookie 和防跨站请求令牌。
- 左侧菜单隐藏、前端路由、页面按钮和后端接口使用同一组权限码；手工输入未授权地址会显示 403，直接请求接口也会被拒绝。
- 公用终端使用完成后，打开右上角头像菜单并点击“退出登录”。退出成功后会清除登录会话和本页安全令牌。

## 5. 当前边界

最高权限账号已经可以在“员工与权限”页面分配预置角色和门店范围。V1 暂不开放自定义新角色、临时授权和可视化权限设计器；需要调整角色默认权限时必须通过受审查的前向迁移和回归测试发布。
