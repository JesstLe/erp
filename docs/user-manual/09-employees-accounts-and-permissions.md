# 员工、登录账号与门店权限

适用版本：V1 员工与权限完整生命周期

更新日期：2026-08-18

## 1. 业务边界

本模块由最高权限账号维护员工基础档案、登录账号、角色和可访问门店。员工档案与登录凭据分开保存：没有登录需求的员工也可以建档；停用登录账号不会删除员工或历史单据。

当前第一版支持新增员工、可选开通账号、编辑姓名和岗位、调动门店、调整角色、办理离职/复职、首次登录强制改密、管理员重置初始密码以及停用/启用账号。临时授权、角色权限设计器、绩效和工资不在本闭环内。

## 2. 员工与账号列表


列表展示员工工号、姓名、岗位、所属门店、登录账号状态和角色。只有 `OWNER` 可以进入“员工与权限”页面；其他角色即使手工输入接口地址也会被服务端拒绝。

查询框支持姓名、工号、登录账号、岗位、门店名称或门店编码。输入停顿约 300 毫秒后列表自动刷新，无需点击查询按钮；继续输入时旧请求会被取消，清空后恢复全部员工。

角色在列表和详情中显示中文业务名称，内部代码只在编辑选项中作为辅助信息。点击某一行可查看详情，并执行资料编辑、离职/复职、密码重置以及账号停用/启用。系统限制：

- 当前登录用户不能变更自己的账号状态，避免把正在操作的会话锁死。
- 系统必须保留至少一个有效 `OWNER` 账号。
- 停用账号后无法新登录；员工档案、业务操作人和审计记录继续保留。
- 账号状态变化会更新安全标记，并记录操作者、门店、时间和前后状态。
- 当前用户不能修改自己的角色或门店范围、办理自己离职、停用自己的账号或由管理员入口重置自己的密码。
- 移除、停用或办理最后一个有效 `OWNER` 离职会被服务端拒绝。

## 3. 新增员工


| 字段 | 是否必填 | 规则 |
|---|---|---|
| 员工工号 | 系统生成 | 品牌内按 `EMP000001` 递增；创建后不可修改、离职后不复用 |
| 员工姓名 | 必填 | 2–100 字 |
| 岗位 | 必填 | 从负责人、店长、前台、收银员、服务员工和其他岗位中选择 |
| 所属门店 | 必填 | 至少一个，只能选择当前操作者有权管理的有效门店 |
| 同时开通登录账号 | 选填 | 未勾选时不能提交账号、密码或角色 |
| 登录账号 | 条件必填 | 开通登录时必填，4–100 位；租户内不可重复 |
| 初始密码 | 条件必填 | 至少 8 位，同时包含英文字母和数字，特殊字符可选；后端只接收并哈希，不回显 |
| 登录角色 | 条件必填 | 开通登录时至少一个；可兼任多个角色 |

“创建员工”在同一数据库事务中写入员工、门店任职、可选登录账号、账号门店范围、角色和审计事件。任一步失败都不保留半成品。

## 4. 首次登录修改密码


管理员不能在保存后查看初始密码。新账号使用初始密码登录后只能进入修改密码页，不能访问其他业务页面。输入当前初始密码和两次一致的新密码后，系统使用 Argon2id 更新密码哈希、清除首次改密标记并刷新当前会话。

不要通过群聊、公开文档或截图传递初始密码；应通过与账号不同的受控渠道单独告知员工。

## 5. 编辑、调动与离职

在员工详情中点击“编辑资料与权限”，可修改姓名、岗位、所属门店及登录角色。保存时提交员工版本号；若其他管理员已经修改，系统返回版本冲突并要求刷新，避免后写覆盖先写。

“办理离职”和“恢复在职”都必须填写 2–200 字原因。离职会立即停用登录账号并刷新安全标记，但不会删除订单、服务提成、操作人或审计历史；复职只恢复员工档案，不自动开启登录账号，负责人核对权限后再单独启用。离职状态下不能编辑资料或重置密码。

管理员重置密码时必须填写符合安全规则的新初始密码和原因。密码正文只用于本次请求，不回显、不进入审计元数据；重置后旧会话失效，员工下次登录必须先修改密码。

## 6. 角色与职责分离

第一版预置角色如下：

| 角色 | 主要用途 |
|---|---|
| `OWNER` | 最高权限、价格发布、账号管理、高风险交班复核和审计 |
| `STORE_MANAGER` | 指定门店经营、录单和授权范围内复核 |
| `FRONT_DESK` | 设施接待与现场操作 |
| `CASHIER` | 本人班次、收款和交班 |
| `TECHNICIAN` | 本人服务任务的受限查看和记录 |

交班复核使用实际登录用户身份判断，不能只看页面按钮。普通店长或收银角色不能复核自己的班次；存在外部待核对金额或较大差额时必须由 `OWNER` 处理。为保证小型门店不会因只有一个最高权限账号而卡死，`OWNER` 可以复核本人班次，但差额说明、操作者身份和状态变化仍完整进入审计。

角色保存后，系统从数据库授权表计算有效权限并返回给前端。左侧菜单、手工 URL、页面按钮和 API 都会重新检查权限；角色只决定能力，门店授权范围另行收口。兼任多个角色时权限取并集，未知角色默认没有业务权限。完整页面矩阵见[角色权限闭环](../modules/role-permission-enforcement.md)。
