# 门店 ERP V1 用户使用手册

> 历史归档：这是 2026-08-20 形成的 V1 合并版，不再作为当前操作依据。当前功能、名词和页面以[项目 README](../../README.md)和[模块化用户手册](README.md)为准。原文中无法证明对应业务状态的旧截图已移除，避免把历史画面误认为当前界面。

版本：V1 本地测试版  
更新日期：2026-08-18

## 1. 手册范围

本手册合并第一版已经运行验收的功能：登录、员工账号、服务项目、产品目录、价格版本、设施接待、顾客会员、服务录单、现金和人工外部收款、交班复核、审计和经营报表。

第一版不包含真实微信/支付宝商户接口、会员储值扣款、退款、采购、产品销售、库存流水、工资和短信。页面出现“人工微信/支付宝”时，只代表门店人员依据实际收款记录进行登记，系统仍保留“待核对”，不能当作渠道到账证明。

所有截图均来自本地虚构数据。

## 2. 角色速查

| 角色 | 第一版主要职责 |
|---|---|
| `OWNER` | 账号与门店权限、目录与价格发布、高风险交班复核、审计和报表 |
| `STORE_MANAGER` | 门店接待、录单、日常收银和授权范围内交班复核 |
| `FRONT_DESK` | 设施接待和现场状态操作 |
| `CASHIER` | 本人班次、收款分摊和提交交班 |
| `TECHNICIAN` | 受限的本人服务任务查看与记录预留 |

前端是否显示按钮不构成授权。服务端会重新校验登录状态、角色、门店范围、业务状态和并发版本。

## 3. 登录和首次改密


输入员工账号和密码进入系统。连续错误会触发临时锁定；“保持登录”只应在受控设备使用。离开公用终端前点击右上角“退出登录”。

新账号第一次使用初始密码登录时，只能进入修改密码页：


新密码至少 8 位，并同时包含英文字母和数字，特殊字符可选。初始密码保存后不回显，管理员也不能查看。

## 4. 初次建账顺序

建议最高权限账号按以下顺序初始化空库：

1. 创建员工，分配门店和角色。
2. 建立服务项目和产品目录。
3. 为全部服务项目和产品创建价格草稿并发布。
4. 配置设施分组、类型和设施。
5. 建立会员卡类。
6. 门店人员开始接待、录单、结算和交班。

## 5. 员工与登录账号


进入“员工与权限”，点击“新增员工”。

| 字段 | 必填规则 |
|---|---|
| 工号、姓名、岗位 | 必填；工号租户内唯一 |
| 所属门店 | 至少一个，只能选择操作者有权管理的门店 |
| 登录账号、初始密码、角色 | 勾选“同时开通登录账号”后必填 |


员工详情支持编辑姓名、岗位、所属门店和角色，也支持办理离职/复职、管理员重置初始密码以及账号停用/启用。离职会停用登录账号但不删除历史单据；复职不自动启用登录。当前用户不能变更自己的权限、办理自己离职、停用自己的账号或从管理员入口重置自己的密码，系统始终保留至少一个有效 `OWNER`。所有高风险变更都记录原因与审计，密码正文不回显、不进入审计日志。

## 6. 服务项目、产品和标准价

服务项目记录项目编码、名称和标准时长。标准时长只作服务参考，不自动收费。


产品目录记录编码、名称、单位和后续库存属性。库存标记当前不生成库存余额或出入库。


所有标准价格由 `OWNER` 在“价格版本”中统一填写。先保存草稿，核对后发布；已发布版本只读，改价必须建立新版本。


金额以整数分保存。服务订单会按门店日期选择已生效版本；同日多个版本按最后发布时间选择。历史订单保存项目名称、编码、标准价和成交价快照。

## 7. 设施接待与独立计时


顾客到店后选择空闲设施，点击“开始使用”。顾客、预计服务、预计时长和备注均可选；顾客与预计服务帮助店长识别本次接待，设施时长和预计服务都不参与自动收费。

设施状态按以下流程变化：

```text
可用 → 使用中 ⇄ 已暂停 → 结束/更换设施 → 待清洁 → 可用
```

- 暂停期间不累计有效使用时长。
- 更换设施要求目标设施可用，旧设施进入待清洁。
- 结束服务后由店长在收银页按实际内容和金额录单。
- 刷新页面后计时由服务器时间继续计算，不依赖浏览器计时器。


## 8. 顾客与会员基础


新建顾客时姓名和手机号必填，姓名按原名展示，手机号加密保存并仅隐藏中间四位。来源、性别、生日和营销同意为选填；营销同意不能由系统默认勾选。

开通会员时选择卡类并填写卡号。系统原子创建储值本金、奖励金和积分三个独立零余额账户。


当前只支持会员基础档案和账户结构，不支持充值、扣款、退款或余额调整。

## 9. 服务录单和金额确认


服务结束后可直接补录，也可选择已结束的设施接待。待录单按顾客原名、预计服务、设施和到店时间展示，机器编号只作追溯；顾客关联可选，允许匿名结算。预计服务必须由操作人明确点击带入，才成为可编辑草稿明细。

每条服务明细必须填写服务项目、数量和成交单价；实际服务时长可选。成交价与已发布标准价不同时，改价原因必填。设施时长、项目实际时长和金额三者独立。

保存后为“待确认金额”；点击“确认金额”后锁定为“待支付”。支付前必须先开班。


## 10. 收款分摊


支付分摊合计必须精确等于服务端锁定的应收金额。

| 支付方式 | 录入要求 | 系统结果 |
|---|---|---|
| 现金 | 金额必填 | 已记录，无需外部渠道对账 |
| 微信/支付宝人工登记 | 金额和交易参考号必填 | 人工登记，始终待核对 |

结算会在一个数据库事务中创建支付单和分摊、结算消费单、完成接待并写入审计。任一步失败整体回滚；幂等请求不会重复收款。


## 11. 开班、交班和独立复核

开班备用金必填，只用于计算理论现金，不计入营业收入。

```text
理论现金 = 开班备用金 + 本班次现金收款
现金差额 = 实际清点现金 - 理论现金
外部待核对 = 本班次人工微信/支付宝分摊合计
```

提交交班时实际清点现金必填，备注选填。异常班次提交后进入“待复核”；普通角色不能复核自己，`OWNER` 可作为最终业务兜底复核本人班次。


现金差额超过 10 元或存在任意外部待核对金额时，必须由 `OWNER` 复核；`OWNER` 即使是本班次操作者也可以完成复核，且存在差额或待核对金额时复核说明必填。


关班不会修改原支付流水，也不会把人工外部收款改成渠道到账。

## 12. 审计记录


“审计记录”按授权门店、动作、对象和日期查询，支持分页和只读详情。记录包含操作者、服务器时间、前后状态、原因、请求号和追踪号，不提供编辑或删除。

请求号用于识别幂等业务命令，追踪号用于服务日志定位；两者都不是支付凭证。

## 13. 经营工作台与报表


经营报表按门店时区查询 1–92 天，分别展示：

- 业务已结算：已结算消费单应收。
- 已记录资金：现金等已记录资金，不含外部待核对。
- 外部待核对：人工微信/支付宝登记。
- 接待数、客单价、每日走势、支付构成、服务项目排行和设施记录时长。

项目排行读取成交快照；设施时长扣除暂停并按查询日期边界裁剪。报表不应把人工登记解释为渠道已到账。

## 14. 不可删除与错误修正

- 已发布价格、已结算消费单、支付分摊、交班快照和审计记录不提供物理删除。
- 当前第一版尚未开放退款/冲正；发现资金错误时先停止继续操作并保留单号、请求号和实际凭证。
- 员工账号停用、目录未来停用都只阻止新业务，不改变历史记录。
- 数据库变更只通过新的前向迁移执行，不修改已部署迁移，不直接手工改生产表结构。
