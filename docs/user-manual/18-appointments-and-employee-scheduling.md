# 预约与员工排班

本模块用于提前安排顾客、服务项目、服务员工和可预约设施。预约只表达计划，到店后才会生成接待记录；设施占用计时和最终收费继续相互独立。

## 权限

- `OWNER`、店长和前台：查看、新增、修改预约，办理到店，取消或记录爽约。
- `OWNER`、店长：查看、新增、修改和取消员工班次。
- 其他角色没有预约管理接口权限。服务端仍会校验租户和门店范围，隐藏菜单不等于授权。

## 新增和修改预约

1. 进入“预约与排班”，选择“预约”。
2. 选择顾客和服务项目，这两项必填。
3. 服务员工和预约设施可不填；设施下拉只显示已启用且在设施配置中勾选“允许预约”的服务位。
4. 填写开始、结束时间和可选备注后保存。预约时长必须为5分钟至24小时。
5. 修改待到店预约时，系统使用版本号校验；页面数据已被他人处理时会要求刷新。

同一员工或同一设施采用半开区间 `[开始, 结束)` 判断冲突，相邻预约可以首尾衔接，重叠预约由服务端拒绝。员工和设施彼此独立，未指定资源不会制造虚假占用。

## 查询

- 默认查询当天至未来14天，按开始时间稳定分页。
- 输入顾客姓名、完整手机号、预约号、项目名称或项目编号后自动加载。
- 完整手机号只在服务端以查询摘要精确匹配；列表仍显示前三位、后四位，中间四位脱敏。
- 可按待到店、已到店、已取消和爽约筛选。

## 到店、取消和爽约

- “到店”会在同一事务创建接待记录，并把预约状态改为已到店。
- 预约指定设施时，到店瞬间再次检查设施是否正在使用或清洁；不可用时不会创建半条接待记录。
- 到店接待会带入顾客、预计项目和预计时长。若预约了设施，同时开始该设施的实际占用计时。
- 到店不会生成金额或自动收费，负责人仍在服务结束后单独录入消费单。
- 取消必须填写原因；爽约只能在预约开始后记录，说明可选。
- 取消和爽约均为状态变化，不物理删除历史。重复提交同一个命令号只返回第一次结果，不重复生成接待或审计事件。

## 员工排班

1. `OWNER` 或店长切换到“员工排班”。
2. 选择当前门店在职员工，填写上班和下班时间；班次必须为30分钟至24小时。
3. 同一员工班次不能重叠，允许首尾衔接。
4. 待执行班次可以修改；取消必须填写原因。取消后只读保留，不可覆盖或删除。

员工班次与预约是两类记录：班次表达出勤计划，预约表达顾客资源计划。当前版本不强制预约必须落在班次内，避免临时加班或跨班服务被错误阻断；冲突仍分别受服务端约束。

## 审计与数据边界

新增、修改、到店、取消、爽约，以及班次新增、修改、取消都会写入操作者、门店、时间、状态和请求号。审计元数据不保存完整手机号。数据库第25版迁移只新增预约和班次表，不修改既有接待、订单、支付或会员流水。
