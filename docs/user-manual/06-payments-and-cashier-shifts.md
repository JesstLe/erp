# 现金、人工外部收款与收款记录

适用版本：V2（2026-10-08 起取消手工开班、交班）

## 1. 业务边界

本模块在金额已经确认的消费单上完成支付分摊、现金记录、微信/支付宝人工登记、消费单结算和收款记录查询。

真实微信或支付宝商户接口已有代码，但没有配置可验收的正式商户凭据。因此：

- 现金由收银员确认实收后记为“已记录”。
- 微信/支付宝由收银员依据实际收款记录人工登记，始终标记为“人工登记 + 待核对”。
- 人工登记可以按当前可逆策略完成业务结算，但绝不会写成“渠道已确认”。
- 会员本金/奖励金扣款已在 V2 扩展模块开放；真实渠道二维码、回调、查单和原路退款代码已具备，但当前门店没有启用真实商户凭据，渠道账单自动对账尚未开放。

## 2. 无需开班或交班

有收款权限的账号可在授权门店直接结算、办理储值，不需要填写备用金或提交交班。新支付和退款不再关联收银班次。历史班次、支付和审计记录仍保留，不自动填写实点现金或完成旧班次复核。

## 3. 组合支付


打开“待支付”消费单，点击“收款结算”。支付分摊合计必须精确等于消费单锁定的应收金额；后端重新读取消费单金额，不接受浏览器提交的总金额作为权威。

停用真实微信、支付宝支付渠道不影响人工结算。店长仍可选择现金、微信人工登记或支付宝人工登记：现金保存为实际收款记录；人工外部收款在消费单上立即完成业务结算，同时保留“人工外部收款待核对”状态，待后续与外部账单复核。仅录入并确认消费金额只会形成“待支付”应收，不代表系统已经收到款项。

| 字段 | 是否必填 | 规则 |
|---|---|---|
| 支付方式 | 必填 | 当前启用现金、微信人工登记、支付宝人工登记和团购人工登记；支付方式由独立配置表提供，不在消费单增加固定渠道金额列 |
| 实收金额 | 必填 | 每行大于 0；所有分摊合计必须等于应收金额 |
| 现金实收 | 使用现金时必填 | 不得小于现金分摊金额；仅表示顾客实际交付的现金，不改变消费单应收 |
| 找零 | 系统计算 | `现金实收 - 现金分摊金额`；由服务端重新计算并与支付单一起保存 |
| 团购平台 | 使用团购时必填 | 当前可选美团、抖音；选择团购支付方式后自动展开，不再需要点击“显示更多” |
| 交易参考号 | 条件必填 | 微信人工登记可留空；支付宝人工登记、团购和其他人工外部收款仍填写 4–100 字参考号，用于之后核对收款记录 |

同一支付方式在一张支付单中只能出现一次。结算按钮只应在已经实际收到对应款项后点击；顾客手机截图、口头说明或二维码页面不等于渠道到账证明。

结算在一个数据库事务中完成：

1. 校验消费单仍为待支付且版本未变化。
2. 校验支付方式有效、分摊平衡和会员账户可用余额。
3. 创建支付单和每一笔支付分摊。
4. 把消费单和接待记录推进为已结算/已完成。
5. 写入幂等结果和审计事件。

任一步失败会整体回滚。双击或网络重试不会产生第二张支付单。

## 4. 结算结果与对账状态


消费单“已结算”表示当前允许的业务支付来源已经平衡，不等于所有外部渠道已完成财务对账。详情分别展示两个状态轴：

| 支付来源 | 收款确认状态 | 对账状态 |
|---|---|---|
| 现金 | 已记录 | 无需外部渠道对账 |
| 微信/支付宝人工登记 | 人工登记 | 待核对 |
| 美团/抖音团购人工登记 | 人工核销登记 | 待核对 |
| 真实微信/支付宝（配置启用后） | 只有合法回调或主动查单才能渠道确认 | 等待渠道账单匹配 |
| 会员内部账户（V2 已开放） | 系统内部扣减成功 | 无需外部渠道对账 |

收款记录和财务报表必须持续显示人工外部待核对金额，直到对账结果明确。不能通过修改消费单状态来掩盖差异。

## 5. 小票打印与补打

已经完成收款的消费单可从详情点击“打印 / 补打小票”。规则如下：

- 第一次打印标记为“顾客联”，第二次起标记为“补打联 #N”。
- 小票使用结算时保存的项目名称、成交单价、数量、服务员工和支付分摊快照；后续目录改名或调价不改变历史小票。
- 现金小票同时展示现金应收、现金实收和找零。
- 每次打印都会由服务端记录支付单、操作者、服务器时间、打印序号和“首次打印/补打”原因；刷新页面或改浏览器不能重置序号。
- 页面使用浏览器打印能力，热敏打印机纸宽、驱动和静默打印策略需要在目标门店设备上验收。

## 6. 收银工作台与退款

收银页提供“今日收银”和“待处理”：前者用于订单查询与日常结算，后者用于改价审批、退款审批和渠道退款处理。收款记录保留操作者、支付方式、时间、金额和待核对状态。

现金退款仍需最高权限批准，受原支付可退额度限制；不再要求审批人开班或按班次备用金校验。审批人应依据实际现金交付办理。会员退款只退回原账户，储值退款仍校验本金和赠金余额。

## 7. 权限、审计与发布

- 收款、退款审批和人工外部对账继续按现有门店权限执行。
- 支付、结算、退款和小票打印继续记录幂等请求号、操作者、时间和审计。
- 支付与退款在事务中执行，失败整体回滚；重复提交不重复入账。
- 原支付、会员流水和历史班次不提供物理删除，错误通过退款或冲正处理。
- 部署前应用 V202610080047__cashiering_without_manual_shifts.sql，就绪检查要求版本 202610080047。
- 历史班次接口保留兼容；旧客户端的交班汇总不能覆盖新版本不关联班次的交易，发布后应统一使用新版本收款记录。

## 8. 营业日报

有报表查看权限的账号可在“服务录单与收银”的“今日收银”区域，以及“经营报表”顶部查看当前门店营业日报。默认日期由服务端按门店时区确定，可选择历史日期，也可点击“今天”返回当日；当日每分钟自动刷新，并提供手动刷新。

表格按现金、微信、支付宝、团购、银行卡、会员本金、会员赠金和其他方式逐行显示。顾客消费与会员储值本金各自列出收款、退款和净额，最后显示合计及当日收款待核对金额。微信、支付宝的人工与真实渠道数据分别归入同一方式，待核对状态继续保留。

消费按结算日、退款按完成日统计，历史订单的当日退款也计入当天，允许出现负净额。净营业额不包含储值本金与赠金；会员余额扣款属于消费，不代表新增现金。赠送金额及退款收回赠金单独显示，不与实收相加。日表按门店与品牌授权隔离，读取失败显示错误，不用零值代替。

## 9. 待确认与未开放

以下内容仍需业务或商户资料确认：

- 人工外部收款是否允许在所有门店完成业务结算，或应按门店开关启用；当前按 `IMP-004` 可逆假设启用。
- 真实微信/支付宝接入主体、商户号范围、回调域名、密钥托管责任和退款审批阈值。
- 签单欠款，以及真实短信服务商的发送和送达回执。
- 财务对人工外部交易执行匹配、差异、解决的页面和凭证要求。
- 非原路退款的受控异常流程；部分/全额原支付退款已经形成审批与反向流水闭环。
