## 范围与安全边界

- 环境：Linux 生产服务器上的测试品牌 `B01`，应用版本 `0.2.0-20260821.3`，schema `202608200032`。
- 测试数据：统一使用 `QA-20260821` 标识，允许在 B01 内新增、修改、取消和结算；不使用真实顾客资金。
- 旧系统：仅只读导出；不执行新增、修改、删除、退款或保存。

- 恢复点：服务器存在导入前和当日 age 加密联合备份，摘要校验通过；私钥不驻留生产服务器，隔离恢复演练仍是正式上线门槛。

## 发现的问题与处理

1. Ant Design 6 右侧详情抽屉在生产浏览器中可能保持 `translateX(100%)`，已在 Web 样式中修复并发布 `0.2.0-20260821.3`。
2. 含人工外部待核对金额的班次要求最高权限复核。早期独立复核规则会让单OWNER品牌形成业务死锁；现行规则已允许OWNER作为最终兜底复核本人班次，同时强制保留说明、差额快照和审计。
3. 首轮旧数据导入把非空门店名称静默回退到第一家旧门店，导致迁移顾客、员工和服务档案集中到 `S002`。导入器已改为旧主键、代码、名称三路匹配，未映射即整批失败；现有 B01 归属需从备份重建或受控重放后逐店对账。
4. 当前旧系统导出包含基础资料、顾客、服务档案文字和照片，但没有可审计的历史消费、支付、退款和储值流水。因此历史经营报表为零不是报表计算错误；只有找到并登记只读历史交易端点、完成字段口径和金额对账后才能迁入。

本轮继续在 B01 测试品牌写入带 QA 标识的虚构数据，不操作其他品牌，也不对旧系统执行任何写请求。

|---|---|

| 积分 | 增加100、扣减30并撤销该扣减，最终余额恢复为100，原流水不覆盖 |
| 次卡 | 购买2次并赠送1次，核销1次后撤销，最终恢复3次；每个动作保留独立流水 |

| 交班 | 理论现金与实交现金均为 ¥163.00，现金差额 ¥0.00、人工外部待核对 ¥0.00 |
| 独立复核 | 交班提交后由另一个测试账号登录、完成首次改密并复核；班次由 `ReviewPending` 推进为 `Closed` |

第一次脚本提交交班返回 `INVALID_ANTIFORGERY_TOKEN`，原因是手工 API 请求没有像前端一样携带 CSRF 请求令牌。补齐 `GET /api/v1/security/csrf` 返回的令牌后同一业务提交成功；这不是交班金额或状态机缺陷，也没有绕过安全校验。
