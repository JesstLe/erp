# 岗位提成与明细页验证

## 验证范围

- 配置：自定义岗位名称；0–100%默认比例与项目单独比例；查询、批量填写、批量清空；现代与经典入口不互相跳转。
- 结算：两条真实后端草稿路径按岗位规则计算，保存当时岗位和来源；历史结算不倒改。
- 查询：全历史或结算日期筛选，授权门店和关键词，SQL汇总、SQL分页、员工汇总、逐笔详情；可重复读事务保持汇总和明细一致。
- 不包含合伙人、产品销售提成、顾问分成、工资发放或凭空补造旧系统提成。

## 专项证据

`PositionCommissionApiTests.PositionRulesRunThroughConfigurationDraftSettlementAndReport` 使用一次性 PostgreSQL、真实 HTTP API 和真实身份验证，已通过：

1. 岗位默认10%，成交80元，提成8元；项目单独15.5%覆盖岗位20%，提成12.40元。
2. 0%不计提；清除项目比例回退默认20%；清除岗位默认回退原项目固定25元。
3. 越界比例、重复项目、跨品牌项目、跨品牌岗位、过期版本、未登录及普通收银员被拒绝。
4. 确认订单后改成90%不倒改原12.40元；后续新单按90%核算72元。
5. 原80元订单退款20元，提成冲减3.10元，净提成9.30元。
6. 两张结算单只返回一行明细时，总计仍为提成84.40元、冲减3.10元、净提成81.30元；与经营报表员工提成一致。
7. 查询旧单号显示原岗位与项目单独比例的快照，不受后改默认影响。

前端专项测试 `PositionCommissionsModal.test.tsx`、`EmployeeCommissionsPage.test.tsx` 已通过5项，包括批量编辑、清空继承、版本提交、独立总计、详情抽屉、自动关键词查询和经典外壳。
