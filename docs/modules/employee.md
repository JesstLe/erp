# 员工模块

![员工模块概览（不含个人记录）](../assets/employee/employee-overview.png)

## 已发现入口

员工信息、绩效考核、员工奖罚、工资核算、支付工资，以及综合业绩、绩效、储值、售卡、服务手工和项目销售等报表。

## 需求拆解草案

- 员工档案与系统账号、组织、门店、岗位和角色关联。
- 绩效规则需要版本、生效期、指标来源和计算解释。
- 奖罚需要事由、证据、审批和工资影响记录。
- 工资核算与支付工资必须隔离权限，并提供核算批次和复核流程。
- 个人薪资、身份证件、联系方式等信息默认严格脱敏。

## 核心业务逻辑

### 核心对象

- 员工档案：个人基础资料、入离职、合同和敏感信息。
- 任职关系：员工所属组织、门店、岗位、职级、生效期和主/兼职关系。
- 系统账号与角色：登录身份、功能权限和数据范围，与员工档案分离。
- 业绩归属：服务员工、销售员工、顾问、多人分享比例和退款冲回关系。
- 绩效方案与结果：指标、权重、周期、规则版本、计算明细、确认和申诉。
- 奖罚与工资：奖罚依据、工资批次、应发、扣减、个税/代扣、实发和支付结果。

### 主流程

```mermaid
flowchart LR
    A["员工入职建档"] --> B["配置任职、账号和权限"]
    B --> C["服务/销售/储值等业务归属"]
    C --> D["形成业绩明细"]
    D --> E["按规则版本计算绩效/提成"]
    E --> F["异常复核与员工确认"]
    F --> G["工资核算批次"]
    G --> H["复核、锁定和发放"]
    H --> I["支付核对与工资凭证"]
```

### 状态与规则

- 员工：待入职 → 在职 → 停职/休假 → 离职；离职不删除历史业务归属。
- 绩效方案：草稿 → 待审核 → 已发布 → 生效 → 失效；已生效规则修改必须新建版本。
- 业绩明细：待确认 → 已确认 → 已计提；退款、退卡或冲正产生反向明细，不覆盖原记录。
- 工资批次：草稿 → 计算中 → 待复核 → 已锁定 → 待支付 → 已支付/部分失败 → 已完成。
- 员工可以跨门店任职，但每段任职关系有明确生效期；权限范围不因任职自动无限扩大。
- 多员工分成按业务单据保存当时的比例和规则版本，比例合计必须满足配置。
- 工资核算只读取已确认的业绩、考勤、奖罚和调整；批次锁定后变化进入下期调整或重开审批。
- 核算人、复核人和支付执行人职责分离；支付失败可按员工重试，不能重复发放成功部分。
- 薪资、证件、联系方式和银行账户按字段授权，查看、导出和修改都记录日志。

### 跨模块关系

- 收银、顾客、销售和促销模块产生服务、销售、储值、售卡、顾问和退款冲回明细。
- 财务模块接收工资应付、实际支付、手续费和失败结果。
- 系统管理提供账号、角色、门店数据范围和审批权限。
- 报表/决策模块读取人员产出、提成成本、工资占比和绩效结果，但默认隐藏个人薪资明细。

## 功能页面遍历结果

| 页面 | 当前界面特征 | 需求结论 |
|---|---|---|
| 员工信息 | 员工档案入口，当前账号下页面结构未完整暴露 | 档案与登录账号、组织、门店、岗位、角色分离；敏感字段分级 |
| 绩效考核 | 新增、修改、删除、查询、打印、导出列表 | 考核方案、周期、指标、权重、评分、申诉和审批形成闭环 |
| 员工奖罚 | 新增、修改、删除、查询、打印、导出列表 | 记录类型、事由、金额/分值、证据、审批和工资影响 |
| 工资核算 | 查询、表格、打印、导出 | 核算批次、计算明细、异常校验、锁定和复核 |
| 支付工资 | 新增、修改、删除、查询、打印、导出列表 | 支付工资不能使用通用CRUD；应采用待支付、复核、支付、失败、完成状态流 |

- 工资汇总表和工资明细表成功打开，提供查询条件、刷新、表格、打印和退出。
- 其余9个入口可见，但点击后没有出现新的可辨识页面；暂记为受限或失效入口。

需求：所有业绩报表必须明确业绩归属规则、多人分成、退款冲回、跨期调整和指标口径；工资报表必须限制到授权人员并禁止普通导出。
