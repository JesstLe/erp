## 核心业务逻辑

决策模块基于报表模块的统一指标，向总部和店长提供目标、趋势、排名、异常和待办；它不重复建设明细报表，也不允许直接修改业务数据。

### 核心对象

- 决策指标：引用指标中心的口径和版本，并定义目标、阈值和观察周期。
- 目标/预算：按组织、门店、指标和周期设定目标值及负责人。
- 异常规则：偏差、连续趋势、排名变化、余额风险和对账差异条件。
- 决策卡片：当前值、目标、同比/环比、样本量、数据截止时间和下钻入口。
- 经营待办：异常责任人、处理期限、处理记录和关闭结果。

### 管理闭环

```mermaid
flowchart LR
    A["统一指标计算"] --> B["与目标、预算和阈值比较"]
    B --> C["生成趋势、排名和异常"]
    C --> D["下钻到门店/员工/项目/单据"]
    D --> E["指派经营待办"]
    E --> F["处理与复核"]
    F --> G["关闭并评估效果"]
```

### 关键规则

- 决策卡片必须显示分母、样本量、时间范围和数据截止时间，避免只展示排名或百分比。
- 排名明确并列规则、最低样本量和新店处理方式；不把小样本极值当作优秀或异常。
- 同比/环比必须使用可比门店和相同口径版本；门店开闭、组织调整需要可比口径说明。
- 重新统计是受控数据任务，记录触发人、原因、口径版本、进度和结果，不能改变业务原单。
- 每日应交款与收银交班、支付渠道、银行存取和费用开支勾稽；差异自动生成待办。
- 储值余额、次卡余次和卡扣余额属于顾客负债视角，不能直接当作收入。
- 所有异常必须能下钻到报表和只读原单；处理动作回到对应业务模块执行。
- 管理层可配置目标和阈值，但不能通过驾驶舱直接修改消费、库存或资金记录。

### 核心关注主题

- 门店经营：营业额、净收入、客流、客单价、复购、毛利和目标达成。
- 顾客资产：会员增长、储值/次卡负债、活跃度、流失和欠款风险。
- 服务与商品：项目/产品结构、销量、毛利、退款率和设施利用率。
- 资金风险：每日应交、支付渠道差异、费用率、工资占比和异常退款。
- 供应链：缺货、周转、滞销、临期、配货满足率和收货差异。

## 目标需求

- 决策指标必须定义口径、粒度、时间范围、组织范围和刷新频率。
- 排名类指标应显示分母、样本量和同比/环比，而非只给名次。
- 关键指标支持下钻到门店、员工、项目、产品和单据。
- 对账、应交款、负债等高风险指标需要异常阈值和待办闭环。
- 统计任务需要显示数据截止时间、生成进度、耗时、口径版本和重新统计原因。
- 排名与占比必须支持最低样本量、异常值说明、同比/环比和可追溯下钻。
- 每日应交款应与收银交班、银行存取、费用开支和门店结算勾稽。
- 无响应的7个入口需由业务决定保留、合并或淘汰，不能直接复制到新系统。
