## 核心业务逻辑

本期财务定位为经营财务与业务台账，不直接替代专业会计总账或法定报表。

微信、支付宝的渠道订单、退款和日账单必须通过统一支付中心进入财务对账，详细规则见 [微信支付与支付宝支付开发设计](../payment-integration-development-guide.md)。

### 核心对象

- 资金账户：现金、银行及其他结算账户，带所属组织、币种、启停状态和余额。
- 业务应收/应付：由消费签单、销售、采购、跨店核算、工资等业务事件产生。
- 收付款与核销：记录实际资金发生及其对应的应收应付分配。
- 费用与其他收入：非采购/销售主链产生的经营收支，包含科目、预算、附件和经办人。
- 内部往来：跨门店服务、储值卡扣、配货和费用分摊产生的内部债权债务。
- 对账记录：支付渠道、银行流水、收银班次和业务台账之间的匹配、差异和处理。

### 主流程

```mermaid
flowchart LR
    A["业务域产生应收/应付或收支申请"] --> B["财务校验来源与金额"]
    B --> C["审核/复核"]
    C --> D["实际收款、付款或转账"]
    D --> E["分配核销来源单据"]
    E --> F["渠道/银行/交班对账"]
    F --> G{"是否有差异"}
    G -- "否" --> H["完成并锁定"]
    G -- "是" --> I["差异调查、调整或冲正"]
    I --> H
```

### 状态与规则

- 应收/应付：待确认 → 已确认 → 部分核销 → 已核销；可争议、暂停、转坏账或冲销。
- 收付款：草稿 → 待复核 → 支付/收款中 → 已完成待核对 → 已核对；可失败、撤销、退款或冲正。
- 费用：草稿 → 待审核 → 已批准 → 待支付 → 已支付 → 已记账；驳回或作废保留原因。
- 对账：待导入/待匹配 → 自动匹配 → 待人工处理 → 已核对 → 已关账。
- 所有资金发生必须关联业务来源或明确的财务原因码；禁止直接改账户余额。
- 收付款与应收应付分离：付款成功不代表已经正确核销，核销关系必须逐笔可追溯。
- 银行存取款按账户间转账处理，支出与存入两边金额必须平衡；手续费独立记录。
- 储值本金与奖励形成不同性质的会员负债；会员消费卡扣按规则减少对应负债。
- 收银交班的理论应交、实际交接和支付渠道对账分别记录；差额需要责任人和处理结论。
- 已核对或已关账记录不可编辑，只能通过调整单或冲正单修复。
- 高风险付款采用金额阈值、双人复核和幂等请求，避免重复支付。
- 微信、支付宝渠道确认与财务“已核对”是两个状态：渠道确认表示支付平台已确认交易，财务已核对表示本地台账、渠道账单和交班金额已经匹配。

### 跨模块关系

- 收银/顾客产生收款、退款、储值负债、签单应收、还款和交班数据。
- 采购产生供应商应付、付款与退货冲减；销售产生客户应收、收款和退款。
- 配货产生配置启用后的内部往来；库存提供成本、盘盈盘亏、报损和调价差额。
- 员工产生工资应付与发放结果。
- 报表/决策读取资金、收入、支出、负债、毛利和对账差异，不能绕过财务状态取草稿数。

## 需求拆解草案

- 单据状态至少包含草稿、待审核、已审核、已记账、已作废。
- 账户、科目、门店、经办人、金额、摘要和附件为基础要素。
- 付款、转账、结算等资金动作必须强权限、双人复核和审计。
- 跨店核算与跨店结算需要明确内部往来和差异处理。
- 首页优先展示待审核、到期应收应付、对账异常和资金风险。

## 功能页面遍历结果

| 页面 | 当前结构 | 关键需求 |
|---|---|---|
| 费用开支单 | 经办人、付款账户、付款金额；费用科目、金额、备注 | 支出申请、审核、付款、记账分离；支持附件和预算控制 |
| 其他收入单 | 经办人、收款账户、收款金额；收入科目、金额、备注 | 明确收入来源、收款渠道和是否应税 |
| 银行存取款 | 支款账户、支出金额；目标科目、存入金额 | 双边账户必须平衡；转账而非单边收支 |
| 跨店核算 | 查询型页面 | 定义跨店服务、储值、卡扣、商品和人员成本的内部结算口径 |
| 跨店结算 | 导入单据、自动/单行分配、应收、本次收款、优惠、结余 | 结算需关联核算明细并记录差异与冲销 |
| 经营情况表 | 查询、刷新、打印 | 指标必须给出口径与数据更新时间 |
| 资产负债表 | 查询、刷新、打印 | 如非正式会计账，应明确其管理报表属性和数据限制 |
