# 平台管理中心与登录安全事件 PRD

更新日期：2026-08-19
状态：本地代码闭环完成，待目标 Linux 发布和运营验收
适用范围：ERP 多商户平台控制面、商户注册申请、商户与平台账号登录安全事件

## 1. 背景与目标

现有 `OWNER` 是单个商户内部的最高权限，所有业务查询都受 `tenant_id` 隔离。服务器虽然保留 Nginx 和 systemd 运行日志，但数据库尚未形成可检索的登录成功、失败、锁定和退出安全事件，也不存在开发者用于管理全部商户的平台控制面。

本模块补齐两个相互关联但必须隔离的能力：

1. 将商户员工和平台管理员的登录行为写入不可由业务页面修改或删除的安全事件，并提供平台级只读查询。
2. 建立独立于商户 ERP 的平台管理中心，处理商户注册申请、商户启停和跨商户运行概览。

## 2. 核心产品决策

- 平台管理员不是 `OWNER` 的扩展角色，不属于任何普通商户，不复用商户 Cookie，也不能从商户员工页面创建。
- 平台入口使用独立路由、独立账号、独立会话 Cookie 和独立服务端授权策略。
- 公开注册只创建“待审核申请”，不直接创建商户、门店或负责人账号。
- 审核通过时由平台管理员设置一次性初始密码；密码不写日志、不进入审计元数据、不在保存后回显。
- 商户停用后，该商户所有员工禁止新登录，已有会话在下一次受保护请求时失效；历史业务和审计数据不删除。
- 平台管理员默认只看商户运营元数据，不直接进入商户业务数据，不查看顾客隐私、会员资金明细或支付密钥。
- 登录失败对外统一返回“账号或密码不正确”，但内部安全事件保留稳定结果码。

## 3. 角色与权限边界

| 身份 | 数据范围 | 允许能力 | 明确禁止 |
|---|---|---|---|
| 未登录访客 | 自己提交的注册申请 | 提交商户注册申请 | 查询商户列表、创建账号、获知账号是否存在 |
| 商户 `OWNER` | 自己的 `tenant_id` | 商户内部员工、门店、业务和审计管理 | 查看其他商户、平台账号、全局登录事件 |
| `PLATFORM_ADMIN` | 平台控制面 | 查看注册申请和商户；审批/驳回；启停商户；查看登录安全事件 | 查看明文密码、支付密钥；直接修改商户业务单据 |

平台协助商户的模拟登录、跨租户业务查看和紧急破窗访问不在本闭环内；未来实现时必须限时、填写原因、显示醒目标识并单独审计。

## 4. 商户注册申请

### 4.1 公开页面

公开入口：`/register`。

| 字段 | 必填 | 规则 |
|---|---:|---|
| 商户/品牌名称 | 是 | 2–100 字 |
| 首店名称 | 是 | 2–100 字 |
| 联系人姓名 | 是 | 2–60 字 |
| 联系手机号 | 是 | 中国大陆 11 位手机号；数据库加密保存，页面只返回脱敏值 |
| 联系邮箱 | 否 | 最多 254 字，必须是合法邮箱格式；数据库加密保存 |
| 期望负责人账号 | 是 | 4–100 位，只允许字母、数字、点、下划线、`@`、连字符 |
| 申请说明 | 否 | 最多 500 字 |
| 同意服务及隐私条款 | 是 | 未勾选不得提交 |

同一手机号摘要或期望账号存在待审核申请时返回冲突；接口按来源 IP 限流。成功后只返回申请编号、状态和提交时间。

### 4.2 状态机

```text
PendingReview ──批准──> Approved
      └────────驳回──> Rejected
```

- 已处理申请不可再次批准或驳回。
- 批准在同一数据库事务中创建商户、首店、标准角色、负责人、员工档案、默认价格策略、会员卡类型和支付方式。
- 任一步失败不得留下半成品商户。

## 5. 平台管理中心

入口：`/platform/login`、`/platform`。

### 5.1 平台登录

- 独立平台账号通过服务器命令行一次性初始化。
- 密码使用 Argon2id；初始账号首次登录必须修改密码。
- 连续 5 次失败锁定 15 分钟；接口按 IP 限流。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Strict`，与商户会话使用不同名称和认证方案。

### 5.2 注册申请页

- 按状态、关键词分页查询。
- 查看脱敏手机号、脱敏邮箱、申请时间和来源 IP。
- 批准时输入商户编码、首店编码、负责人初始密码和审批原因。
- 驳回必须填写原因。

### 5.3 商户页

- 展示商户编码、名称、状态、门店数、员工数、登录账号数、创建时间。
- 支持按名称/编码实时查询，按状态筛选和服务端分页。
- 可启用或停用商户；操作必须填写原因并使用并发版本号。
- 平台页面不得提供物理删除商户按钮。

### 5.4 登录安全事件页

- 展示时间、范围（商户/平台）、结果、已识别账号、商户、IP、设备摘要和追踪号。
- 支持按范围、结果、商户、账号关键词、日期分页查询。
- 页面只读，不提供新增、修改、删除和批量清空。

## 6. 登录安全事件模型

事件类型：

- `LoginSucceeded`
- `LoginFailed`
- `AccountLocked`
- `LogoutSucceeded`
- `PasswordChanged`
- `PasswordResetByAdmin`

每条事件至少记录：事件 ID、范围、租户 ID（可空）、已识别用户 ID（可空）、不可逆账号 HMAC、脱敏账号、结果码、来源 IP、User-Agent 摘要、追踪号和服务器 UTC 时间。

安全要求：

- 不记录密码、Cookie、防跨站令牌、完整请求体和支付密钥。
- 未识别账号只保存 HMAC 和脱敏显示，避免建立明文撞库字典。
- User-Agent 截断并规范化，最长 200 字。
- 登录结果写入失败不得把正确密码误报为错误；事件持久化异常写入应用日志并返回通用系统错误。
- 在线保留年限和冷归档策略后续确认；当前不提供删除接口。

## 7. API 契约

### 7.1 公开接口

- `POST /api/v1/public/merchant-registration-applications`

### 7.2 平台认证

- `POST /api/v1/platform/auth/login`
- `GET /api/v1/platform/auth/csrf`
- `GET /api/v1/platform/auth/me`
- `POST /api/v1/platform/auth/change-password`
- `POST /api/v1/platform/auth/logout`

### 7.3 平台资源

- `GET /api/v1/platform/registration-applications`
- `POST /api/v1/platform/registration-applications/{id}/approval`
- `POST /api/v1/platform/registration-applications/{id}/rejection`
- `GET /api/v1/platform/merchants`
- `POST /api/v1/platform/merchants/{tenantId}/status-change`
- `GET /api/v1/platform/security-events`

所有列表使用 `page`、`pageSize` 和稳定筛选参数；所有错误沿用 `{ error: { code, message }, traceId }`。写接口启用防跨站请求保护，登录和公开申请分别限流。

## 8. 数据库与升级

采用仅向前迁移，新增：

- `platform_admin_users`
- `merchant_registration_applications`
- `login_security_events`
- `platform_audit_events`

不修改现有业务表主键，不删除历史数据。为 `organization_tenants.status`、申请状态/时间、安全事件时间/范围/结果建立查询索引。应用升级失败只能回退兼容新 schema 的代码，不自动降级数据库。

## 9. 验收标准

1. 商户正确登录、错误密码、第五次失败锁定、退出分别生成对应安全事件，事件不含密码。
2. 未知账号失败不会泄露账号是否存在，平台事件仅显示脱敏账号。
3. 商户 `OWNER` 无法调用任何 `/api/v1/platform/*` 受保护接口。
4. 平台管理员不能使用平台 Cookie 调用商户业务接口。
5. 公开申请经过限流和字段校验，只形成 `PendingReview` 申请。
6. 批准申请原子创建一个商户、一个首店和一个必须首次改密的 `OWNER`；重复审批返回冲突。
7. 停用商户后员工不能登录，已有会话不能继续访问受保护业务接口；恢复后可重新登录。
8. 平台页面可以分页查询全部商户、注册申请和登录安全事件，但不返回密码哈希、手机号明文或支付密钥。
9. 数据库迁移、单元测试、真实 PostgreSQL API 测试、前端测试、lint、生产构建和依赖审计全部通过。

## 10. 暂不包含

- 短信或邮件验证码、自动发送初始密码。
- 套餐计费、在线订阅和试用到期自动扣费。
- 平台管理员模拟登录商户。
- 商户数据导出、迁移和物理删除。
- 多因素认证和硬件密钥；正式大规模商用前应列为平台管理员必做项。
