# 系统管理模块

## 模块目标

为全部业务模块提供组织、门店、用户、角色、数据权限、审批、业务参数、支付方式、编号规则、集成和审计能力。系统管理只配置规则和权限，不直接替业务模块修改业务单据。

## 核心对象

- 租户/品牌、区域、门店、仓库、部门和岗位。
- 用户、员工绑定、角色、功能权限、动作权限、字段权限和数据范围。
- 审批流程：适用单据、金额阈值、角色、节点、加签和生效期。
- 业务参数：编号规则、原因码、状态字典、交班规则、负库存策略和数据保留策略。
- 支付方式：现金、外部渠道、会员账户、签单等分类及核对方式。
- 集成配置：支付、短信、打印、银行或其他第三方账户、Webhook和同步任务。
- 审计：登录、权限变更、敏感查看、配置变更和高风险业务操作日志。

## 主流程

```mermaid
flowchart LR
    A["创建组织与门店"] --> B["创建员工和用户绑定"]
    B --> C["分配角色与数据范围"]
    C --> D["配置审批、参数和外部集成"]
    D --> E["发布配置版本"]
    E --> F["业务模块按版本执行"]
    F --> G["日志、异常和权限复核"]
```

## 权限规则

- 权限至少包含模块、页面、动作、字段、组织范围、金额阈值和数据条件。
- 最高权限账号拥有最终定价和关键策略发布权，但日常操作仍应留痕；不能因为是老板账号就跳过审计。
- 员工档案与登录用户分离；停用账号不删除员工历史业务记录。
- 权限遵循最小授权和职责分离：制单/审核、核算/支付、模板配置/短信发送、价格维护/门店改价不得默认合并。
- 临时授权必须有起止时间、原因和审批人；过期自动回收。
- 支付渠道配置和OWNER角色授权属于最高风险配置：存在第二个有效OWNER时由另一人复核；仅有一个OWNER时要求二次认证、影响预览并生成高风险待办和完整审计。
- 门店或组织停用前校验未完成单据、在途库存、余额和未关班次，不能直接消失。

## 配置与版本规则

- 影响业务结果的参数必须版本化并记录生效时间，历史单据继续引用原版本。
- 支付方式配置包含类别、是否需要外部参考号、确认来源、手续费和对账方式；新增渠道不修改核心单据表。
- 编号规则保证租户和单据类型范围内唯一；打开页面不提前永久占号，草稿占号和回收规则透明。
- 审批流程修改不改变已经在途的审批实例，除非通过受控迁移。
- 外部账户密钥加密保存且不回显；修改需要重新认证和审计，必要时双人复核。
- 配置发布前提供影响预览：受影响门店、业务类型、生效时间和冲突项。

## 审计与异常

- 日志记录操作者、角色、组织、会话、时间、对象、动作、前后值、原因、审批链、请求号和结果。
- 资金、库存、会员权益、薪资、价格、权限、短信和敏感导出日志采用不可篡改保留策略。
- 集成任务记录请求、响应摘要、幂等号、重试次数和最终状态；敏感内容脱敏。
- 权限或配置变更后立即使相关缓存失效；当前会话权限下降时页面同步降权。

## 待确认

- 审计日志、业务数据和导出文件的保留期限。
- 支付、短信和银行集成第一期实际接入范围。

## 已确认的第一期组织边界

- 第一期服务一个品牌下的总部、区域和多个门店，不开放多商户 SaaS 管理后台。
- 核心业务表仍保留 `tenant_id`，第一期由系统写入固定品牌租户，所有查询同时执行租户和门店数据范围校验。
- 新系统空库启动，由最高权限账号完成品牌、门店、角色、员工、服务项目和价格等初始化，不导入旧系统历史业务数据。

## 数据库与发布治理

系统管理负责展示而非绕过数据库治理：

- 显示当前应用版本、数据库schema版本和最近发布结果。
- 展示备份、WAL归档、恢复演练和磁盘容量状态，但不向普通管理员开放任意SQL。
- 配置变更走版本和审批；数据库结构变更只能通过受控迁移发布。
- 生产应用账号不拥有DDL权限，系统页面不提供通用SQL执行入口。
- 具体规则见 [数据库设计与变更治理规范](../database-design-and-change-governance.md) 和 [Windows单机部署与容量基线](../windows-server-deployment-baseline.md)。
