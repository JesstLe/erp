# 自定义岗位与服务提成

## 需求与范围

岗位名称由品牌自行维护，不固定行业名称或等级。“初级”“中级”“高级”可以分别建成岗位，也可使用“课程老师”“安装工程师”等名称。员工选择岗位后，本次服务按该岗位的提成规则核算。合伙人、利润分红、工资发放不在本次范围。

现代版、经典版均在“员工 → 岗位设置”提供“提成设置”，经典版不跳转到现代版。岗位创建或修改后可直接设置提成；岗位规则绑定不可变的岗位编号，不绑定名称。

## 配置与计算规则

界面文案仅保留操作说明、计算规则、数据状态与必要校验；“合伙人暂未纳入”等开发范围说明留在本文档，不展示给用户。经典页面同样不展示后端接入、状态机、缺口文档或复刻实现说明。未开放的操作明确提示“暂不可用”或“内容未保存”，不能伪装为保存成功或没有业务数据；权限、折扣、提成和退款计算规则不因文案清理而改变。

岗位设置弹窗采用简明引导：“提成只算一次，不叠加”，先填岗位通用比例，个别项目再单独填写；两处留空使用服务项目原设置，0%明确不计提。表格显示最终数值及“单独比例／岗位通用／服务项目原设置”来源，用“20%与15%，实收100元提15元，不是35元”示例解释。仅调整展示和说明，不改变后端计算、保存接口或历史订单。

- 岗位默认提成比例可选，支持 0–100%，最多两位小数；留空沿用服务项目原有规则，0% 明确不计提。
- 可在表格中查询服务项目，为每个项目填写单独比例；留空沿用岗位默认比例。允许批量设置或清除项目单独比例。
- 优先级：岗位＋项目单独比例 → 岗位默认比例 → 服务项目原有提成（比例、固定金额或无提成）。
- 仅服务项目产生服务提成，产品“添加人”归属与现有产品无提成逻辑不变；顾问分成不属于此规则。
- 比例计算基数为服务行最终成交金额（含数量，会员价或手动改价后），四舍五入到分；不以设施计时或储值充值作为基数。
- 必须选择当前品牌、当前门店有效员工，才能使用员工岗位提成。未选员工时保留原有项目提成必填校验，不猜测岗位。
- 岗位停用只影响新的岗位分配，已在该岗位的员工仍按其岗位规则核算。
- 草稿保存或重新编辑保存时读取当前规则；已确认或已结算的单据保留提成快照，改岗位、改名或改规则不会倒改历史；现有退款冲减和收益报表口径不变。

## 数据与接口

`organization_employee_positions` 增加可空的 `default_commission_rate_basis_points`；100 基点=1%。新增 `organization_position_service_commissions`，记录品牌、岗位、服务项目和单独比例，品牌＋岗位＋项目唯一。仅增量扩展，不迁移或重算历史金额；原岗位默认留空。

`GET /api/v1/employees/positions/{id}/commissions` 返回岗位、版本、默认比例及本品牌全部服务项目和单独比例。

`PUT /api/v1/employees/positions/{id}/commissions` 全量替换该岗位的单独比例，并设置默认比例；提交 `expectedVersion`，用事务保存配置及审计。项目不在本品牌、项目重复、比例越界或版本冲突均拒绝。请求最多 2000 条单独规则。普通员工无员工管理权限时不能读写；前端隐藏不作为权限边界。

## 提成查询页面

现代版新增“员工提成”独立入口；经典版在员工模块内进入“员工提成明细”，保持各自外壳。默认显示授权门店全部历史已结算的服务提成，提供门店、结算日期、员工/单号/项目关键词查询及分页。草稿、待支付、作废单与产品添加人不进入此表。

页面上方显示筛选范围内的服务成交金额、提成毛额、退款冲减、净提成、结算单数、服务数量；中间按员工汇总，下方逐笔展示结算时间、门店、单号、员工工号/姓名、当时岗位、项目、数量、成交金额、提成方式和参数、规则来源、毛提成、冲减和净提成。总计不受明细分页影响。以原结算时间筛选，退款冲减包含这些订单截至查询时的已完成累计退款，不是所选日期的工资发放。

新订单同时保存当时岗位编号/名称和规则来源；旧订单无岗位快照时显示“历史记录未保存”，不从当前岗位反推。退款分摊保持现有按整单比例、四舍五入到分且不超过毛提成的口径。管理员和获报表权限的店长仅能查看其授权门店，其他品牌、未授权门店、普通收银员不能读取这些金额。旧系统未导出/未关联员工的提成不得伪造生成。

`GET /api/v1/reports/employee-commissions` 接受门店、起止日期、关键词、页码和每页条数（1–100）；返回全范围汇总、员工汇总及分页明细。缺省日期代表不限日期，统一按照返回的统计时区划分日期。

## 员工档案内查询服务与提成

现代“员工与账号”列表及详情提供“服务与提成”按钮，经典员工列表在选中员工后提供同名按钮；在当前界面弹窗查看，不跳转其他UI。默认当天，支持当天、近7天、近30天、全部历史及自定义起止日期，也可再筛选授权门店和单号/项目关键词。关闭再打开或切换员工重新初始化，清空筛选不能解除员工绑定。

使用员工不可变ID精确筛选，不使用姓名或工号关键词模拟关联；同名、改名、离职员工均能查看其已有记录。后端仍强制品牌与授权门店范围，普通收银员不得通过直接调用读取。

姓名查询仍然支持：员工列表可输入姓名筛选后点开该员工，独立员工提成页也可按姓名或工号检索，匹配当前姓名或当时姓名快照；同名结果分别显示工号和门店，不把姓名当成唯一身份。

展示工号、当前姓名/岗位/所属门店，范围内结算单数、服务明细数、数量、成交金额、提成毛额、退款冲减及净提成；逐笔展示结算时间、门店、消费单号、服务项目、数量、录入服务时长、目录单价、最终单价、价格来源、当时岗位、提成规则/来源与金额。详情中的价格和岗位以订单快照为准，不从当前目录或岗位倒推。

服务记录口径为“已结算、已关联该服务员工的服务行”，按结算日期筛选；未结算、作废、产品销售、储值充值、护理老师记录不混入收入提成。退款冲减包含所选订单截至查询时的累计退款。没有记录显示空态；加载失败明确提示，不把未知金额显示成真实0。汇总覆盖全部匹配记录，不随明细翻页变化，不等同于工资已发放。

扩展已有GET接口可选 `employeeId`，与关键词/门店/日期条件求交集；空UUID或非法分页、日期拒绝，不匹配的员工返回空集合。仅扩展查询与DTO，无数据库表变更、无金融写入。

## 岗位规则验收

1. 自定义两个岗位，默认比例分别为 10%、20%；同一 100 元服务对应提成 10、20 元。
2. 岗位默认 20%，项目单独 15.5%，实际成交 80 元时提成为 12.40 元。
3. 单独 0% 覆盖默认；清空单独比例回退到默认；清空默认回退到项目原有规则（包括固定金额）。
4. 现代设施接待、经典操作台及服务录单两条后端草稿路径读取同样规则；结算后员工收益报表使用快照。
5. 修改规则后已确认订单不变；跨品牌项目、无权限访问、越界比例、重复项目和过期版本被拒绝。
6. 岗位无提成配置时与旧系统行为一致，产品提成仍为零。
