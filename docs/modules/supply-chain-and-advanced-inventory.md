# 供应链与高级库存实现说明 v1

## 1. 已实现范围

本模块对应整改项 P2-03，当前实现以下本地闭环：

- 供应商档案：系统自动生成品牌内 `SUP000001` 形式编码；用户维护名称、联系人、联系电话、结算条款、启用/停用，更新受版本冲突保护。
- 采购入库：供应商、门店、外部票号、说明、产品、数量、单位成本、批次号和可选有效期。
- 批次库存：入库生成批次，出库按“最早到期优先、无有效期最后”的顺序分摊；批次剩余量不得为负。
- 库存盘点：提交时冻结账面数量，审批时只过账“实盘数－冻结账面数”；盘点期间发生的正常销售、退货或入库不会污染盘点差异。
- 职责分离：盘点申请人与审批人必须是不同账号；申请人不能自批。
- 跨店调拨：待出库、在途、已收货、已取消四态；确认出库才扣调出店，确认收货才增加调入店。
- 成本和效期传递：跨店调拨按原批次保留批次号、有效期和单位成本。
- 审计与幂等：过账动作使用请求号防重复，库存余额、不可变流水、批次分摊和审计记录在同一数据库事务内提交。

## 2. 权限

| 操作 | 最高权限 | 店长 |
| --- | --- | --- |
| 查看供应商 | 是 | 是 |
| 新增、编辑、停用供应商 | 是 | 否 |
| 查看/过账采购入库和采购成本 | 是 | 否 |
| 查看批次、数量和效期 | 是 | 是 |
| 查看单位成本 | 是 | 否，接口返回0且页面不显示成本列 |
| 发起盘点 | 是 | 是，仅限授权门店 |
| 审批盘点 | 是，且不能审批本人申请 | 否 |
| 取消待审批盘点 | 是 | 是，仅限授权门店 |
| 新建、出库、收货、取消调拨 | 是 | 否 |

## 3. 数据与不可变规则

- 前向迁移：`V202608180028__supply_chain_advanced_inventory.sql`。
- 新增主表：`suppliers`、`purchase_receipts`、`purchase_receipt_lines`、`inventory_lots`、`inventory_lot_allocations`、`stocktakes`、`stocktake_lines`、`inventory_transfers`、`inventory_transfer_lines`、`inventory_transfer_lots`。
- 历史非零库存迁移为成本0的 `LEGACY-*` 批次，不改写原库存余额和流水。
- 采购入库单及明细、批次分摊、盘点明细、调拨明细和调拨批次快照由数据库触发器禁止更新和删除。
- 库存流水新增 `PurchaseReceipt`、`StocktakeGain`、`StocktakeLoss`、`TransferOut`、`TransferIn` 类型。
- 已过账事实不提供编辑或物理删除；纠错必须使用新的反向业务单据，保留原事实。

## 4. 交互入口

侧栏“采购与供应链”包含五个页签：批次效期、库存盘点、跨店调拨、供应商、采购入库。采购入库表单明确区分必填字段和可选字段；盘点、采购和调拨均允许多产品行。

## 5. 当前边界

本阶段没有把采购订单、采购退货、供应商应付/付款、多仓库库位、税额、加权成本结转和财务凭证纳入 P2-03。它们仍属于采购财务扩展，不得把本地采购入库闭环表述为完整采购财务闭环。

本地测试只能证明工程实现：112项领域测试、30项集成测试（其中核心流程使用真实 HTTP/PostgreSQL）及14项前端测试通过；真实门店仍需用实物批次完成盘点、过期预警和跨店签收验收。
