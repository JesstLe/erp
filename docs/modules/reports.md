## 核心业务逻辑

报表模块是“可追溯的业务分析中心”，不创建或修改原业务数据。它使用统一指标口径，从已达到指定业务状态的事实数据中生成汇总和明细。

### 核心对象

- 指标定义：名称、业务含义、公式、来源、粒度、组织范围、时间口径和版本。
- 维度：日期、门店、顾客、会员卡类、项目、产品、员工、支付方式和业务单据类型。
- 报表定义：指标集合、筛选器、默认排序、权限和下钻路径。
- 保存视图/订阅：用户保存的筛选、列、计划时间和接收方式。
- 报表任务与导出：生成范围、数据截止时间、状态、文件、下载人和审计信息。

### 数据流程

```mermaid
flowchart LR
    A["各业务模块已生效事件"] --> B["统一事实与维度模型"]
    B --> C["按指标版本计算"]
    C --> D["汇总报表"]
    D --> E["继承筛选下钻明细"]
    D --> F["订阅/受控导出"]
    E --> G["回到只读业务单据"]
```

### 关键规则

- 每个指标必须标明采用制单日期、业务日期、支付日期还是审核/入出库日期。
- 草稿、作废和失败记录默认不计入经营结果；退款、退货和冲正按原业务期间与报表口径处理。
- 汇总、明细和下钻必须使用同一指标版本与筛选范围，避免数字对不上。
- 报表展示数据截止时间、更新时间和延迟状态；数据未完成时不能显示为最终结果。
- 顾客、薪资、成本、毛利和账户数据继承源模块字段权限；导出权限不等于页面查看权限。
- 大报表使用异步任务，状态为排队、生成中、成功、部分失败、失败和过期。
- 导出文件记录条件、列、行数、脱敏方式和下载行为，并设置有效期和水印。
- 报表只读；从报表调阅单据不能携带编辑、删除或审核权限。

### 模块边界

- 报表回答“发生了什么、明细是什么”，面向日常运营查询。
- 决策模块回答“是否异常、为什么、需要采取什么行动”，面向管理层聚合和预警。
- 两者共享同一个指标口径中心，不能各自计算一套营业额、毛利或会员负债。

## 目标需求

- 统一时间、组织、门店和业务口径筛选器。
- 每张报表展示指标定义、更新时间、数据范围和权限说明。
- 支持收藏、最近使用、订阅与角色推荐。
- 汇总数字可下钻到明细，但需继承原筛选条件和权限。
- 导出视为受控动作，记录导出人、条件、时间和数据范围。
- 年龄和渠道等图形报表必须同时提供表格、样本量和“未知/未填写”分组。
- 顾客消费与支付方式报表包含姓名和手机号时，姓名按原名展示、手机号仅隐藏中间四位；单据下钻需重新校验数据范围权限。
- 毛利、负债、卡扣、次卡消耗必须显示公式、成本口径和跨期调整说明。
- 报表运行要有生成中、无数据、失败、超时和数据延迟状态，不能只显示空白图表。
