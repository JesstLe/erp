# 跨模块交互、权限与审计规范

## 1. 目标

新 ERP 保留参考系统“业务域工作区 + 统一单据/报表骨架”的优点，但把查看、编辑和业务状态变化彻底分离，避免多层 iframe、隐式写入和高风险动作平铺。

## 2. 页面类型

| 页面类型 | 固定结构 | 主要状态 |
|---|---|---|
| 模块首页 | KPI、异常待办、趋势、最近单据、快捷入口 | 加载中、正常、无数据、部分失败、权限不足 |
| 列表/查询 | 页面标题、快速筛选、高级筛选、视图、表格、分页 | 初始、查询中、无结果、失败、部分字段受限 |
| 单据编辑 | 基本信息、明细、金额、附件、状态流、日志 | 新建草稿、编辑、校验失败、提交中、提交成功、并发冲突 |
| 单据详情 | 摘要、业务明细、上下游关系、审批、日志 | 草稿、待审核、已审核、执行中、完成、作废 |
| 分析报表 | 口径说明、筛选、指标、图表、表格、下钻 | 生成中、数据延迟、无数据、失败、完成 |
| 高风险任务 | 影响预览、原因、复核人、二次确认 | 待确认、处理中、部分成功、失败、完成 |

## 3. 动作风险分层

| 等级 | 示例 | 交互要求 |
|---|---|---|
| R0 查看 | 打开页面、切换视图、查看详情 | 不得产生业务写入；记录访问日志仅由基础设施异步完成 |
| R1 草稿 | 新建/编辑草稿、保存筛选视图 | 自动保存需明确提示；可撤销；不影响库存、余额或财务 |
| R2 提交 | 提交单据、发起审批、预约、开始服务 | 展示影响摘要并要求明确确认；生成业务事件 |
| R3 资金/库存 | 审核、出入库、付款、退款、结算、工资发放 | 独立权限、二次确认、幂等、防重复提交、完整审计 |
| R4 不可逆/对外 | 作废已生效单据、短信群发、批量导出敏感数据 | 双人复核或审批、范围预览、原因、通知与事后追踪 |

## 4. 单据状态模型

所有业务单据至少区分：草稿 → 已提交 → 待审核 → 已审核 → 执行中 → 已完成；另有驳回、撤回、作废、冲销。保存草稿不占用库存、不变更余额、不记账；审核或执行动作通过独立命令产生库存、资金或权益流水。

状态动作必须返回唯一请求号和结果，不允许重复点击造成重复入库、重复扣款或重复发送。并发修改时展示冲突字段和最新版本，禁止静默覆盖。

## 5. 权限模型

- 组织范围：总部、区域、门店、仓库、本人。
- 对象权限：模块、页面、单据类型、报表。
- 动作权限：查看、新建、编辑、提交、审核、执行、导出、作废。
- 字段权限：手机号、身份证、薪资、成本、毛利、账户、余额等独立控制。
- 数据条件：创建人、经办人、所属门店、状态、金额阈值。
- 职责分离：制单与审核、核算与发放、配置账户与发送短信、采购与付款不得由同一高风险权限包自动兼任。

## 6. 审计与可追溯

操作日志记录：操作者、角色、组织、设备/会话、时间、动作、对象、变更前后、原因、审批链、请求号和结果。资金、库存、会员权益、薪资、短信和敏感导出日志采用不可篡改保留策略。

报表下钻继承原筛选与权限；导出记录条件、列、行数、脱敏方式、文件有效期和下载人。敏感文件使用水印、加密和限时链接。

## 7. 隐私与安全

- 列表默认隐藏完整手机号、身份证、薪资和账户密钥；查看明文需单独权限并留痕。
- 搜索、导出、截图和打印遵循同一字段权限，前端隐藏不能替代后端授权。
- 短信收件人必须校验营销同意、退订、频控、黑名单、时间窗和敏感词。
- 密钥和密码永不回显；修改账户需要重新认证，关键配置支持双人复核。

## 8. 关键异常与恢复

- 无网络/超时：保留草稿，明确是否已提交，支持使用同一请求号重试。
- 部分成功：展示成功与失败明细，禁止把批量任务误报为整体成功。
- 库存/余额不足：阻止执行并指出冲突对象、当前值和可选处理方式。
- 权限变化：当前页面立即降权，敏感缓存失效。
- 报表延迟：展示数据截止时间、预计完成时间和口径版本。
- 离开表单：提示未保存变更；系统单号和草稿占用规则透明、可回收。

V1具体角色、动作、字段权限和审批阈值见 [V1角色权限与审批阈值矩阵](v1-role-permission-and-approval-matrix.md)。
