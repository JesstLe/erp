# ERP V2 范围与交付计划

更新日期：2026-08-18

## 完成定义

V2 只有在下列业务链均具备数据库迁移、服务端权限与幂等、可操作前端、自动化测试、真实本地浏览器验收和用户手册后，才可标记完成：

| 顺序 | 业务链 | 当前状态 | 关键验收 |
|---|---|---|---|
| V2-01 | 会员储值与分账 | 已完成首个闭环 | 本金/奖励分账；支付来源；交班汇总；收入不混算 |
| V2-02 | 会员余额消费与验证码 | 待开发 | 余额原子扣减；本金/奖励顺序；达到 500 元核对手机号与 OTP |
| V2-03 | 消费与储值退款/冲正 | 待开发 | 从原单发起；累计退款不超原单；最高权限批准；反向流水 |
| V2-04 | 微信/支付宝真实渠道 | 待商户资料后开发 | Native/订单码、回调验签、查单、幂等、对账、原路退款 |
| V2-05 | 产品销售与库存 | 待开发 | 销售快照、出入库流水、并发防超卖、退货反向流水 |
| V2-06 | 审批与字段权限增强 | 待开发 | 改价、赠送、退款、敏感字段查看与导出可审计 |
| V2-07 | 更新、备份与 Windows 测试部署 | 待开发 | 一键迁移/发布、回滚策略、备份恢复演练、运行监控 |

## 已交付的 V2-01

- 新增兼容式迁移 `V202608180008`，现有消费支付原地回填业务来源，消费单关联继续保留。
- 支付单使用通用业务来源区分消费与会员储值；经营收入只统计消费，交班仍统计全部实际收款。
- 储值本金、奖励金和支付分摊强制平衡；会员账户不能购买自身储值。
- 本金和奖励金分别写入不可变账户流水，数据库使用余额非负、流水唯一和并发令牌保护。
- 现金/人工外部收款要求当前操作员开班；人工外部记录保持待对账。
- 正奖励金仅 `OWNER` 可确认；店长和收银员只能处理无赠送储值。
- 完成表单、账户余额和储值历史回显，并保留本地虚构截图。

## 下一条实现链

V2-02 从“消费单待支付”进入会员账户分摊：先增加完整手机号核对与一次性验证码挑战，再在同一事务内校验余额、扣减本金/奖励金、写借方流水和结算消费单。OTP 必须有短有效期、尝试次数限制、一次性使用和审计，测试环境使用可控发送适配器，生产环境不得回显验证码。
